# 3교시 Codex 활용하기

> `@onboard`로 시작해 본인 파일을 읽고 설명받은 뒤, PPT·개발문서·업무문서 초안 만들기로 연결합니다. Codex 초보자 기준으로 한 단계씩 확인합니다.

---

## 내 업무 공간이란

`tes-workmate`는 내 업무를 위한 Codex 작업 폴더입니다. 설치할 때 이 PC에서 최근에 쓰던 업무 파일의 목록과 본문을 미리 읽어 두고, 온보딩에서 그 내용으로 내 업무를 확인합니다. 쓸수록 기록·규칙·스킬이 쌓입니다.

- 분석은 내 PC의 Codex 안에서만 합니다. 파일을 밖으로 보내지 않습니다.
- 최근 업무 파일이 거의 없으면 직무별 가상 예시 자료로 세팅됩니다.
- 회사 정보는 공개 자료로 만든 것이라 사내 사정과 다를 수 있습니다.

1교시에 설치하지 못했다면 지금 [1교시 안내](#mixed-1-01-warmup)의 설치 한 줄을 붙여 넣습니다.

---

## 순서

### 1. 설치와 폴더 확인

1교시에 실행한 설치 창에 `설치 완료`가 보이는지 확인합니다. Codex 앱에서 Windows `문서\tes-workmate`, Mac `~/Documents/tes-workmate` 폴더를 프로젝트로 엽니다.

**확인할 것:** 프로젝트 이름이 `tes-workmate`인지, 교육 폴더와 다른 내 업무 공간을 열었는지 봅니다. 설치 오류나 진행 중 표시가 있으면 강사에게 알립니다.

### 2. `@onboard`로 시작하기

대화창에 아래 요청을 복사합니다.

```text
@onboard
```

**예상 화면:** Codex가 업무 공간에 준비된 파일 목록과 알고 있는 업무 내용을 보여 주고, 확인할 번호 선택지를 제안합니다.

**확인할 것:** Codex가 실제로 읽은 파일 이름과 경로를 보여 주는지 봅니다. 모르는 파일이나 개인정보·사내 기밀 파일이 보이면 사용하지 말고 강사에게 알립니다.

### 3. 본인 파일 읽기·설명

교육 폴더에는 개인정보와 사내 기밀을 넣지 않습니다. 공개 자료, 가상 자료, 회사에서 교육용으로 허가한 자료만 사용합니다. 아래 요청으로 파일을 먼저 설명받습니다.

```text
이 업무 공간에서 내가 선택한 파일을 먼저 읽고, 파일 형식·작성 목적·핵심 내용·모르는 부분을 초보자에게 설명해 줘. 아직 요약 파일이나 결과물을 만들지 마. 실제로 읽은 파일 경로도 적어 줘.
```

**예상 화면:** 파일별 설명과 읽은 경로가 나옵니다.

**확인할 것:** 파일을 실제로 읽었는지, 추정과 파일에서 확인한 사실이 구분되는지 확인합니다. 틀린 부분은 `이 부분은 틀렸어. 원자료를 다시 확인해 줘`라고 말합니다.

### 4. 업무 결과물 초안 만들기

설명을 확인한 뒤 결과물 종류 하나를 고릅니다.

**PPT 초안** — TES 공통 템플릿으로 만드는 `/ppt-draft`를 씁니다.

```text
/ppt-draft 방금 읽은 자료로 팀장 보고용 PPT 초안 만들어 줘. 설명에 도움이 되는 그림이 있으면 생성해서 넣어 줘.
```

Codex가 먼저 슬라이드 계획(장마다 제목·핵심 내용·차트나 그림 여부)을 보여 주고 승인을 기다립니다. 계획을 확인한 뒤 `1. 계획 승인`과 표지에 넣을 이름·소속을 보냅니다. 만드는 데 5~10분쯤 걸립니다.

**확인할 것:** 제목은 핵심만 짧고 본문에 수치와 설명이 들어갔는지, 숫자 하나가 원자료와 같은지, 생성 그림 아래에 `이미지: AI 생성`이 적혔는지 봅니다. 만든 PPTX는 `reports/`에 저장되고 PowerPoint에서 바로 고칠 수 있습니다. PPT에 필요한 프로그램은 설치 때 자동으로 준비됩니다. 회사 PC 정책으로 설치가 막혀 Codex가 "PPT 도구를 준비하지 못해 보고서로 만듭니다"라고 알리면 손을 들고, 그 보고서로 계속합니다.

**개발문서 초안**

```text
방금 읽은 자료를 바탕으로 초보 개발자도 이해할 수 있는 개발문서 초안을 만들어 줘. 먼저 목차·독자·각 절에서 설명할 내용을 보여 주고, 확인하기 전에는 파일을 만들지 마.
```

**업무문서 초안**

```text
방금 읽은 자료를 바탕으로 업무문서 초안을 만들어 줘. 먼저 문서 목적·독자·핵심 결론·근거 자료를 보여 주고, 확인하기 전에는 파일을 만들지 마.
```

계획을 읽고 아래처럼 선택해 파일을 만듭니다.

```text
좋아. 방금 제안한 계획으로 초안을 만들어 줘. 원자료에 없는 숫자나 사실은 넣지 말고, 확인이 필요한 부분은 [확인 필요]로 표시해 줘. 저장한 파일 경로를 알려 줘.
```

**예상 화면:** Codex가 권한을 물은 뒤 초안 파일을 만들고 경로를 알려 줍니다.

**확인할 것:** 권한 대상이 `tes-workmate` 안인지, 결과 파일을 직접 열었는지, 원자료에 없는 내용이 표시되었는지 확인합니다. 사실 하나를 원자료와 대조합니다.

### 5. 검토와 한 번 고치기

```text
초안을 검토해 줘. 빠진 내용·원자료와 다른 내용·읽기 어려운 표현을 각각 표로 보여 줘. 아직 파일은 고치지 마.
```

검토 결과를 보고 한 곳만 고칩니다.

```text
[고칠 문장이나 슬라이드]만 고쳐 줘. 원자료의 내용과 파일 구조는 유지하고 다른 부분은 그대로 둬.
```

**확인할 것:** 지정한 곳만 바뀌었는지, 원래 파일도 남아 있는지 확인합니다.

## 온보딩 뒤 따라 하기

| 순서 | 보내는 말 | 확인할 것 |
|---|---|---|
| 1. 회사 질문 | `우리 회사 주력 장비가 뭐고, 내 부서는 그 안에서 어떤 일을 하는지 3줄로` | 답에 근거 문서 링크가 있는지 |
| 2. 내 스킬 만들기 | `2교시에 한 분석 절차를 내 공간 스킬로 만들어 줘` | 입력·결과물·규칙·완료 기준 네 가지를 묻거나 채우는지, `.agents/skills/`에 새 스킬이 생겼는지 |
| 3. 스킬 써 보기 | `방금 스킬로 다른 기간 자료도 해 줘` | 두 번째 결과가 같은 순서로 나오는지 |
| 4. 규칙 남기기 | `앞으로 그래프 제목에는 항상 기간을 넣어 줘` | `AGENTS.md` 5장에 규칙이 들어갔는지 |
| 5. 정리 | `정리해 줘` | 오늘 한 일이 기록으로 남았는지 |

---

## 각자 — 내 업무 한 건

마지막은 각자 합니다.

1. 내 업무 하나를 말로 시킵니다. 온보딩 답에 나온 업무 선택지에서 골라도 됩니다.
2. 결과 파일을 직접 열어 봅니다.
3. 숫자나 사실 하나를 원자료와 대조합니다.
4. 고칠 점 하나를 말로 요청합니다. 고칠 곳만 지정하고 "다른 건 그대로"를 붙입니다.

결과 파일 하나가 남으면 됩니다.

## 교육 뒤에 쓰는 세 마디

| 이럴 때 | 이렇게 말합니다 |
|---|---|
| 일이 끝났을 때 | `정리해 줘` |
| 고쳐 주고 싶은 점이 있을 때 | `앞으로 항상 …` |
| 같은 일을 또 할 때 | `스킬로 만들어 줘` |

내 업무 공간은 교육이 끝난 뒤에도 그대로 씁니다. 자료를 더 넣고 싶으면 `최근 파일 더 모아 줘`라고 보냅니다.
