# 1교시 Codex 첫걸음과 플러그인

> Codex를 처음 쓰는 분을 기준으로, 강사 화면을 보며 폴더 열기·첫 요청·다운로드 폴더 정리·플러그인 사용까지 하나씩 따라 합니다. 미리 해 보지 못한 분도 1교시에 함께 진행합니다.

---

## 1교시에서 배우는 순서

오늘은 강사 화면을 보며 **같이 하나씩 해 보는 시간**입니다. 본인의 다운로드 폴더를 써도 되고, 준비가 안 된 분은 안내 페이지의 예제 ZIP을 받아 같은 흐름으로 따라갑니다.

1. 강사 소개와 오늘 만들 결과 확인
2. 사람이 일하는 다섯 단계 이해
3. Codex가 일하는 방식 이해
4. 화면에서 교육 폴더 열기
5. 첫 요청 보내기와 응답 읽기
6. 권한 요청과 파일 생성 확인
7. 다운로드 폴더를 살펴보고 정리 계획 세우기
8. 플러그인 마켓플레이스 등록·설치·맛보기

각 단계에서 **설명 읽기 → 요청문 복사 → 화면 확인 → 다음 단계** 순서로 진행합니다. 모르는 단어가 나와도 먼저 멈추지 말고 강사 화면과 같은지 확인합니다.

## Codex 설치는 교육 전에 준비합니다

이 페이지를 보기 전에 Codex 데스크톱 앱을 설치하고 회사 계정으로 로그인해 둡니다. 테스 교육은 Codex 앱에서 진행합니다. 설치하지 못했거나 로그인·업데이트에서 막힌 분은 교육 당일 손을 들어 알려 주세요.

**첫 휴식 시간에 하는 일:** 1교시를 마친 뒤, 2교시를 시작하기 전에 Codex가 준비되지 않은 분을 보조강사가 돕습니다. 이때 2교시 실습 폴더와 함께 3교시 `tes-workmate` 공간도 준비합니다. 1교시 실습을 멈추고 설치를 기다리지는 않습니다.

## 1. 강사 소개와 오늘의 목표

강사가 소개하는 동안 다음 세 가지를 확인합니다.

- 오늘 사용할 프로그램이 ChatGPT 안의 **Codex**인지
- 내가 직접 교육 폴더를 열고 요청을 보내는지
- 요청한 뒤 Codex의 답과 파일을 내가 확인하는지

화면 왼쪽 위에 `Codex`가 보이면 준비된 것입니다. 아직 다른 화면이면 강사 화면을 보고 Codex로 전환합니다.

## 2. 사람이 일하는 다섯 단계

Codex에게 일을 시킬 때도 사람이 일할 때처럼 순서를 나눕니다.

| 단계 | 쉬운 뜻 | Codex에게 하는 말 |
|---|---|---|
| 1. 업무 파악 | 무엇을 하려는지, 가능한지 묻기 | “이 자료로 무엇을 할 수 있어?” |
| 2. 기획 | 방법을 여러 개 보고 내가 고르기 | “방법을 3개 제안해 줘. 아직 만들지는 마.” |
| 3. 만들기 | 고른 방법대로 결과 만들기 | “2번 방법으로 만들어 줘.” |
| 4. 검토 | 결과가 맞는지 다시 확인하기 | “빠진 것과 틀릴 수 있는 곳을 검토해 줘.” |
| 5. 개선 | 고칠 곳만 정해 다시 요청하기 | “표의 제목만 고쳐 줘. 다른 것은 그대로.” |

**확인할 것:** Codex가 한 번에 모든 일을 해 주는 것이 목표가 아닙니다. 내가 지금 어느 단계인지 알고 다음 행동을 고르는 것이 목표입니다.

## 3. Codex가 일하는 방식

Codex는 대화만 하는 도구가 아니라, 내가 프로젝트로 연 폴더의 파일을 읽고 요청에 따라 파일을 만들거나 고칠 수 있는 도구입니다.

- 대화창에 쓴 요청을 읽고 작업 방법을 제안합니다.
- 파일을 읽거나 만들기 전에 필요한 권한을 물을 수 있습니다.
- 작업한 뒤 무엇을 했는지와 파일 경로를 알려 줍니다.
- 답변을 그대로 믿지 말고, 파일과 숫자를 직접 열어 확인합니다.
- 권한 요청이 이해되지 않으면 **허용하지 않고 강사에게 먼저 묻습니다.**

다음 요청문을 복사해 보내며, 아직 파일을 만들지 않습니다.

```text
Codex가 할 수 있는 일과 할 수 없는 일을 초보자도 이해할 수 있게 3가지씩 설명해 줘. 지금은 파일을 만들거나 고치지 말고 대화로만 답해 줘.
```

**예상 화면:** Codex가 읽기, 파일 만들기, 파일 수정, 명령 실행처럼 할 수 있는 일을 설명합니다. 한 번에 여러 일을 하자고 제안할 수도 있습니다.

**확인할 것:** 답변에 “지금은 파일을 만들지 않는다”는 요청이 지켜졌는지, 파일 경로가 실제로 생기지 않았는지 확인합니다.

## 4. 교육 폴더를 화면에서 열기

1. 과정 안내에서 받은 `tes-lab.zip`의 압축을 풉니다.
2. Codex 앱을 열고 왼쪽 위가 `Codex`인지 확인합니다.
3. **폴더 열기** 또는 프로젝트 추가를 누릅니다.
4. 압축을 푼 `tes-lab` 폴더를 선택합니다.
5. 폴더 안에 `1교시-몸풀기`, `2교시-...`, `README.md`가 보이는지 확인합니다.
6. 권한 선택 화면이 나오면 강사 화면과 같은 기본값을 선택합니다. 모르는 권한은 승인하지 말고 손을 듭니다.

**예상 화면:** 왼쪽 파일 목록에 `tes-lab` 안의 폴더와 파일이 보이고, 오른쪽에 새 대화 화면이 열립니다.

**확인할 것:** 다른 개인 폴더를 연 것이 아닌지, 파일 목록의 최상위 폴더 이름이 `tes-lab`인지 확인합니다. 교육 중에는 이 교육 폴더만 사용합니다.

## 5. 첫 요청 보내기

폴더를 열었으면 아래 문장을 그대로 복사해 보냅니다.

```text
지금 열려 있는 교육 폴더의 이름과 바로 안에 있는 파일·폴더를 초보자에게 설명해 줘. 파일을 만들거나 고치지는 마.
```

**예상 화면:** Codex가 현재 폴더 이름과 안에 있는 항목을 목록으로 보여 줍니다. 파일을 바꾸지 않았다고 안내할 수 있습니다.

**확인할 것:** 답변의 폴더 이름이 화면의 프로젝트 이름과 같은지, 파일을 만들거나 고치지 않았는지 확인합니다. 답이 이해되지 않으면 `각 항목을 한 줄씩 더 쉽게 설명해 줘`라고 보냅니다.

## 6. 응답 읽기와 다음 요청 고르기

Codex 답변은 다음 네 부분으로 읽습니다.

1. **무엇을 이해했는지:** 내가 말한 요청을 어떻게 해석했는지
2. **무엇을 했는지:** 파일을 읽었는지, 만들었는지, 아직 아무것도 안 했는지
3. **어디에 남겼는지:** 파일 경로와 파일 이름
4. **무엇을 확인할지:** 내가 직접 열어 볼 항목

다음 요청문으로 이 네 부분을 다시 구분해 봅니다.

```text
방금 답변을 초보자용으로 다시 정리해 줘. ① 네가 이해한 일 ② 실제로 한 일 ③ 아직 하지 않은 일 ④ 내가 화면에서 확인할 일을 각각 한 줄로 써 줘. 파일은 만들지 마.
```

**예상 화면:** 답변이 네 항목으로 나뉘어 나옵니다.

**확인할 것:** “제안했다”와 “실제로 파일을 만들었다”를 구분할 수 있는지 확인합니다. Codex가 하지 않은 일을 했다고 쓰면 `실제로 확인한 것만 다시 써 줘`라고 요청합니다.

## 7. 권한과 파일 생성 확인

이번에는 안전한 교육 폴더 안에 작은 파일 하나를 만들어 봅니다. 파일을 만들기 전에 권한 확인 창이 뜨는지 살펴봅니다.

```text
1교시-몸풀기 폴더 안에 첫-확인.txt 파일을 만들어 줘. 파일에는 “Codex가 만든 첫 파일” 한 줄만 써 줘. 만들기 전에 무엇을 할지 설명하고, 권한이 필요하면 창에서 확인할 수 있게 기다려 줘.
```

**예상 화면:** Codex가 파일을 만들겠다고 설명한 뒤 권한 승인 창을 보여 줄 수 있습니다. 승인 후 작업이 끝나면 파일 경로를 답합니다.

**확인할 것:**

- 권한 창에 표시된 대상이 교육 폴더인지
- 파일 이름이 `1교시-몸풀기/첫-확인.txt`인지
- 파일을 직접 열었을 때 한 줄만 들어 있는지
- Codex가 말한 경로와 실제 파일 위치가 같은지

권한 창의 내용이 다르거나 삭제·외부 전송·개인 폴더 접근을 요청하면 **거부**를 누르고 강사에게 알립니다. 권한은 무조건 허용하는 버튼이 아닙니다. 무엇을 허용하는지 읽고 선택합니다.

## 플러그인 설치와 맛보기

플러그인은 Codex에 특정 작업 방법을 더해 주는 기능 묶음입니다. 먼저 강사 화면을 보며 마켓플레이스를 등록하고, 사용할 플러그인을 설치한 뒤 같은 요청을 보내 봅니다.

### 마켓플레이스 등록과 설치

1. 아래 주소를 복사합니다.

   **[GPTaku Codex 마켓플레이스](https://github.com/fivetaku/gptaku-plugins-codex)**

2. Codex의 플러그인 메뉴를 엽니다. 화면에 `/plugins`를 입력하거나 왼쪽 메뉴의 **Plugins**를 선택합니다.
3. **Marketplace 추가** 또는 **Add marketplace**를 선택합니다.
4. 방금 복사한 GPTaku Codex 마켓플레이스 주소를 붙여 넣고 등록합니다.
5. 등록된 마켓플레이스에서 **Insane Search Codex**, **Insane Research Codex**를 찾아 설치합니다.
6. 목록에 마켓플레이스가 보이지 않거나 등록에 실패하면 앱을 완전히 끄고 다시 켠 뒤 강사에게 알립니다.
7. 설치가 끝나면 **새 대화**를 엽니다. 설치한 플러그인은 새 대화에서 사용합니다.

> 플러그인 설치가 1교시 시간 안에 끝나지 않아도 괜찮습니다. 설치 과정을 함께 확인한 뒤, 막힌 분은 강사 시연을 보고 2교시 전 휴식 시간에 보조강사의 도움을 받습니다.

### 첫 번째 맛보기 — 공개 자료 찾기

`insane-search`는 잘 열리지 않는 공개 페이지나 뉴스의 내용을 찾아 읽는 용도입니다. 먼저 무엇을 하려는지 설명하고 요청합니다.

```text
지금은 공개 뉴스 1개를 찾아 실제로 열리는지 확인하는 연습을 합니다. insane-search로 오늘 반도체 장비 업계 뉴스 1개를 찾아 제목·날짜·한 줄 요약·주소를 표로 정리해 줘. 확인하지 못한 내용은 쓰지 마.
```

**예상 화면:** 검색 결과 표와 출처 주소가 나옵니다. 인터넷 사용 권한을 묻는 창이 나오면 강사와 같은지 확인합니다.

**확인할 것:** 주소를 눌렀을 때 실제 페이지가 열리는지, 표의 제목과 날짜가 페이지와 같은지 봅니다. 인터넷 결과는 반드시 원문과 대조합니다.

### 두 번째 맛보기 — 출처를 대조하는 짧은 조사

`insane-research`는 여러 출처를 대조해 짧은 보고서를 만드는 용도입니다.

```text
지금은 여러 출처를 비교하는 연습을 합니다. insane-research로 HBM 투자 확대가 증착 장비 수요에 미치는 영향을 출처 3개 이상으로 짧게 정리해 줘. 출처마다 확인한 주장과 주소를 함께 적고, 확실하지 않은 내용은 추정이라고 표시해 줘.
```

**예상 화면:** 짧은 설명과 출처 목록 또는 보고서 파일 경로가 나옵니다. 조사에 시간이 걸리면 강사 안내에 따라 멈추고 다음 단계로 갑니다.

**확인할 것:** 출처가 실제로 열리는지, 보고서의 주장과 출처가 연결되는지, 사실과 추정이 구분되는지 확인합니다.

요청문 앞에 `insane-search로`, `insane-research로`처럼 플러그인 이름을 쓰지 않으면 원하는 플러그인이 사용되지 않을 수 있습니다.

## 1교시가 끝나면

다음 항목을 직접 확인합니다.

- 교육 폴더 `tes-lab`를 Codex 프로젝트로 열었다.
- 본인 다운로드 폴더 또는 예제 ZIP 폴더를 열었다.
- 첫 요청을 보내고 Codex의 응답에서 한 일과 하지 않은 일을 구분했다.
- 권한 창의 대상과 파일 생성 결과를 확인했다.
- 다운로드 폴더를 살펴보고 정리 계획을 세웠다.
- 플러그인 마켓플레이스를 등록하고, 가능하면 플러그인 2개를 설치해 맛봤다.

플러그인이나 Codex 준비가 끝나지 않은 분은 1교시를 멈추고 기다리지 않습니다. 첫 휴식 시간에 보조강사의 도움을 받아 2교시를 시작할 수 있게 준비합니다.

마지막으로 처음 대화로 돌아가 `다음`을 보냅니다. 1교시에는 파일을 살펴보고 정리 계획을 세운 결과와 첫 확인 파일, 플러그인 사용 경험이 남습니다.
