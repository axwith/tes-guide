## 1. 실습 폴더 받기

**[1교시 실습 폴더 받기 (1교시-Codex-시작하기.zip)](/downloads/1교시-Codex-시작하기.zip)**

1. 위 링크로 ZIP 파일을 받습니다.
2. 압축을 풉니다.
   - Windows: 받은 파일을 오른쪽 클릭 → **모두 압축 풀기** → **찾아보기**를 눌러 **바탕 화면**을 고르고 → **압축 풀기**
   - Mac: 받은 파일을 더블클릭하고, 생긴 폴더를 바탕 화면으로 옮깁니다.
3. `1교시-Codex-시작하기` 폴더 안에 `downloads` 폴더, `outputs` 폴더, `README.md`가 보이면 됩니다. 열었는데 `1교시-Codex-시작하기` 폴더가 한 번 더 보이면, 그 안쪽 폴더를 씁니다.


`downloads` 폴더에는 영수증·사진·설치 파일·압축 파일·중복 파일처럼 실제 다운로드 폴더에 있을 법한 데모 파일 46개가 들어 있습니다.

## 진행 방법

1교시는 블록 0부터 블록 4까지 다섯 블록입니다.

1. Codex 답의 맨 아래에는 **지금 보낼 말**이 하나 있습니다. 그 문장을 그대로 복사해 보냅니다.
2. Codex가 실제로 처리하고, 확인할 것과 다음에 보낼 말을 보여 줍니다. 블록이 끝나면 확인 결과와 다음 블록 설명이 이어서 나옵니다.
3. 앱 화면에서 하는 단계(블록 2 플러그인 설치)만 보낼 말이 `했어요`입니다.

막히면 `도와줘`, 시간이 모자라면 `건너뛰기`를 보냅니다. 아래 요청문은 Codex가 보여 주는 요청문과 같습니다. 강사 화면과 Codex 화면을 우선해 따라 하고, 이 페이지는 참고용으로 봅니다.

## 블록 1. 다운로드 폴더 정리

업무와 상관없는 소재로 5단계를 한 바퀴 돕니다. 2교시(웹 자료 분석 자료)와 3교시(내 업무 공간)도 같은 순서로 진행합니다. 블록을 시작할 때 Codex가 먼저 파일 수를 세고 `준비 완료: downloads 파일 46개.`라고 알립니다. 요청문은 아래 표 순서대로 하나씩 나옵니다.

| 단계 | 복사할 요청문 | 확인할 것 |
|---|---|---|
| ① 업무 파악 · ② 기획 | `downloads 폴더가 엉망이야. 정리하고 싶은데 어떻게 하면 좋을까? 먼저 어떤 파일이 몇 개 있는지 보고, 정리 계획을 outputs/계획.md로 저장해 줘. 만들 폴더 이름, 파일마다 어디로 갈지, 중복으로 보이는 파일과 애매한 파일은 어떻게 할지 적어 줘. 아직 아무것도 옮기지 마.` | 답에 전체 46개와 종류별 개수가 나왔는지, 계획.md에 46개가 모두 있고 중복 3쌍이 표시됐는지, 파일이 하나도 안 움직였는지. 마음에 안 드는 폴더 이름은 직접 고쳐 저장해도 됩니다 |
| ③ 만들기 · ④ 검토 | `outputs/계획.md대로 정리해 줘. 파일은 지우지 말고 옮기기만 해. 끝나면 폴더별 파일 수를 표로 보여 주고, 정리 전과 후 파일 수가 같은지, 계획.md와 다르게 들어간 파일이 없는지 검토해서 outputs/정리결과.md로 저장해 줘.` | 탐색기(Mac은 Finder)로 downloads를 열어 폴더가 생겼는지, 정리결과.md에 정리 전·후 개수와 "다르게 들어간 파일" 칸이 있는지. 폴더 하나는 내 눈으로 열어 봅니다 |
| ⑤ 개선 · 중복 정리(지우기 거절해 보기) | `영수증 폴더만 파일 이름 앞에 날짜를 붙여서 날짜순으로 보이게 해 줘. 날짜는 파일 이름이나 수정한 날짜에서 찾아 줘. 그리고 중복 파일은 지워 줘. 이 두 가지 말고 다른 건 그대로.` | 영수증 폴더 파일만 이름이 바뀌고 다른 폴더는 그대로인지. 중복 파일은 Codex가 바로 지우지 않고 지울 목록과 번호 선택지를 보여 주는지. 다음 보낼 말로 나오는 `3`(그만두기)을 보내 거절합니다. 승인 창이 뜨면 **거부**를 누릅니다 |

![다운로드 정리 결과 예시(이전 흐름의 화면이라 아래 보낼 말은 지금과 다를 수 있습니다)](/images/rnd/r1-07-block1-result.jpg)

**끝나면 남는 것:** `outputs/계획.md`, 정리된 `downloads` 폴더, `outputs/정리결과.md`

## 블록 2. 플러그인 설치

플러그인은 Codex에 기능 묶음을 더하는 것입니다. GPTaku 플러그인 마켓(`gptaku-plugins`, [github.com/fivetaku/gptaku_plugins](https://github.com/fivetaku/gptaku_plugins))을 등록하고, 목록을 보며 어떤 플러그인이 있는지 살펴본 뒤 쓸 만한 13개를 설치합니다. 실습은 그중 두 개(insane-research, pumasi)로 합니다.

블록을 시작할 때 Codex가 먼저 설치 상태를 읽어 한 줄로 알립니다(예: `마켓 등록 안 됨, 플러그인 13개 중 0개 설치됨.`). 이미 된 단계는 건너뜁니다. 이 블록은 앱 화면에서 하는 일이라 보낼 말이 `했어요`입니다. 화면에서 막혀 `도와줘`를 보내면 Codex가 대신 설치할 문장을 보낼 말로 보여 줍니다.

**① 마켓 등록**

1. 왼쪽 아래 계정(아이디) 아이콘을 누르고 **설정**을 엽니다.
2. **통합** → **플러그인**으로 갑니다.

   ![플러그인과 스킬과 MCP를 관리하는 설정 화면](/images/rnd/r1-09-plugins.jpg)

3. 오른쪽 위 **추가**를 누르고 **마켓플레이스 추가**를 고릅니다.

   ![GPTaku 플러그인 마켓플레이스 주소를 입력한 창](/images/rnd/r1-10-market-add.jpg)

4. 저장소 주소에 `https://github.com/fivetaku/gptaku_plugins`를 넣고 등록합니다.
5. 다 했으면 대화창에 `했어요`를 보냅니다. Codex가 ② 설치 안내를 보여 줍니다.

막혔을 때 Codex가 보여 주는 문장:

```text
GPTaku 플러그인 마켓을 등록해 줘
```

**확인할 것:** 등록할 때 오류가 나지 않았는지 봅니다. 문장으로 했다면 승인 창의 명령에 `gptaku_plugins`가 있는지 읽고 승인합니다.

**② 목록 보며 설치**

1. Codex 창 맨 왼쪽 아이콘 줄에서 **플러그인** 아이콘(위에서 네 번째, 동그라미 속 @ 모양)을 누릅니다. **맞춤 설정** 화면이 열립니다.
2. **플러그인** 제목 아래 **개인용** 탭을 누릅니다. 방금 등록한 **GPTaku plugins** 목록이 보입니다. 몇 개만 보이면 목록 아래 "… 등 더 보기"를 눌러 전체를 펼칩니다.
3. 아래 표의 13개를 옆의 **+** 로 설치합니다(`gptaku-core` 먼저).
4. **공개** 탭에는 Gmail·Teams·Canva·Figma 같은 일반 서비스 플러그인이 있습니다. 오늘은 설치하지 않고, 나중에 필요한 것을 같은 방법으로 설치해 씁니다.

![맞춤 설정 → 플러그인 → 개인용 탭의 GPTaku plugins 목록과 '더 보기'](/images/rnd/r1-11-plugin-list.jpg)

| 플러그인 | 오늘 | 한 줄 설명 |
|---|---|---|
| gptaku-core | 설치(먼저) | 다른 플러그인이 함께 쓰는 기본 묶음 |
| insane-research | 설치·실습 | 여러 출처를 찾아 조사 보고서를 만들어 줍니다 |
| pumasi | 설치·실습 | 그림·썸네일·포스터 같은 이미지를 만들어 줍니다(큰 코딩 작업 나눠 맡기기도 가능) |
| insane-search | 설치·2교시 실습 | 잘 안 열리는 사이트(X, 레딧, 네이버, 유튜브 등)의 글·영상 내용을 가져와 읽습니다 |
| docs-guide | 설치 | 프로그램·도구의 공식 문서를 찾아 쉽게 설명해 줍니다 |
| show-me-the-prd | 설치 | 아이디어를 말하면 기획서(PRD) 초안을 바로 써 줍니다 |
| skillers-suda | 설치 | 반복하는 일을 Codex 스킬로 만들어 줍니다 |
| kkirikkiri | 설치 | 여러 AI 에이전트로 팀을 꾸려 일을 나눠 맡깁니다 |
| vibe-sunsang | 설치 | 내 AI 사용 기록을 보고 성장 코칭을 해 줍니다(시간이 남으면 마지막에 써 봅니다) |
| insane-loop | 설치 | 아이디어 → 기획 → 완성까지 검증하며 반복합니다 |
| goaljaby | 설치 | 기획서를 목표 실행 문서로 바꿔 끝까지 진행시킵니다 |
| playmaker | 설치 | 목표 진행 상황을 카드 보드로 보여 줍니다 |
| tikeytaka | 설치 | 흩어진 API 키를 한곳에 안전하게 모아 관리합니다 |

표에서 '설치'로 표시한 13개(`gptaku-core` 먼저)를 설치합니다. 1교시 실습은 그중 `insane-research`와 `pumasi` 두 개로 블록 3에서 이어 쓰고, `insane-search`는 2교시에서 씁니다. 나머지는 필요할 때 같은 화면에서 설치합니다. 다 했으면 대화창에 `했어요`를 보냅니다.

막혔을 때 Codex가 보여 주는 문장:

```text
오늘 쓸 GPTaku 플러그인 13개를 설치해 줘
```

![GPTaku plugins 전체 목록에서 13개를 설치해 왼쪽 설치됨에 보이는 화면](/images/rnd/r1-12-installed.jpg)

**확인할 것:** 승인 창이 뜨면 승인합니다. 표의 13개가 설치됨으로 보이는지 봅니다. 특히 `insane-research`와 `pumasi`.

설치를 확인하면 Codex가 플러그인 부르는 법을 짧게 알려 줍니다. 요청문 맨 앞에 플러그인 이름(`insane-research로`, `pumasi:image로`)을 붙이면 그 기능을 쓰고, 이름을 빼면 Codex 기본 기능으로 합니다. 블록 3 요청문이 이렇게 시작합니다.

**③ 새 대화로 옮기기**

플러그인은 새 대화부터 쓰입니다.

1. 왼쪽 목록에서 프로젝트 이름(`1교시-Codex-시작하기`)을 눌러 새 대화를 엽니다.
2. 새 대화에 `@lab1`을 보냅니다. 블록 2 확인과 블록 3 설명, 블록 3의 첫 요청문이 바로 이어서 나옵니다.

이제부터는 새 대화에서 진행합니다. 설치가 막히면 강사 화면 시연을 보고 넘어갑니다.

## 블록 3. 오늘 이슈 설명 자료 만들기

업무와 상관없는 "오늘 화제가 되는 이슈"로 플러그인 두 개를 이어 씁니다. insane-research로 이슈 3개를 찾고, 하나를 골라 pumasi로 설명 그림을 만들고, 둘을 묶어 한 장 설명 자료를 만듭니다.

**① 오늘 이슈 찾기 — insane-research**

```text
insane-research로 오늘 국내에서 화제가 되는 이슈 3개를 찾아 줘. 이슈마다 무슨 일인지 세 줄로 정리하고 출처 주소를 하나씩 붙여서 outputs/오늘이슈.md로 저장해 줘. 깊게 조사하지 말고 짧게 끝내 줘.
```

**확인할 것:** 범위를 묻는 질문이 나오면 가장 짧은 쪽을 고릅니다. 인터넷 사용 승인 창이 뜨면 승인합니다. `outputs/오늘이슈.md`에 이슈 3개와 출처 주소가 있는지 봅니다.

![outputs/오늘이슈.md가 저장되고 세 가지 이슈가 제시된 답](/images/rnd/r1-13-issues.jpg)

**② 하나 고르기**

Codex가 찾은 이슈 3개를 번호로 보여 줍니다. 그림과 설명 자료로 만들 이슈의 번호만 보냅니다. Codex가 `{번호}` 자리를 고른 번호로 채운 요청문을 다음 보낼 말로 보여 줍니다.

**③ 그림과 한 장 설명 자료 — pumasi · HTML**

이 요청문은 이 페이지가 아니라 **Codex 화면에서 복사**합니다. Codex가 `{번호}` 자리 두 곳을 고른 번호로 채워 보여 줍니다. 그림을 만들고, 그 그림을 넣은 HTML 한 장까지 한 번에 만듭니다.

```text
pumasi:image로 outputs/오늘이슈.md의 {번호}번 이슈를 설명하는 그림 1장을 Codex 이미지 기능으로 만들어서 outputs/이슈그림.png로 저장하고, 그 그림과 {번호}번 이슈로 한 장 설명 자료를 outputs/이슈설명.html로 만들어 줘. 그림 안에 글자는 넣지 말고 가로로 넓게, 묻지 말고 알아서 골라 줘. HTML은 파일 하나로 열리게 하고 인터넷에서 글꼴이나 라이브러리를 불러오지 마. 그림은 맨 위에, 출처 링크는 맨 아래에 작게 넣어 줘.
```

**확인할 것:** `outputs/이슈그림.png`를 열어 그림이 이슈와 어울리고 글자가 없는지 봅니다. `outputs/이슈설명.html`을 더블클릭해 브라우저에서 그림·설명·출처가 보이는지 봅니다.

![1번 이슈(한지 제작 전통) 설명 그림 예시(이전 요청문 화면이라 말풍선 문장은 지금과 다릅니다)](/images/rnd/r1-14-image.jpg)

![생성한 이슈설명 HTML을 브라우저에서 연 결과 예시](/images/rnd/r1-15-html.jpg)

이슈 찾기나 그림이 오래 걸리면 기다리지 말고 `건너뛰기`를 보냅니다. 이슈 찾기는 그때까지 찾은 내용만 짧게 저장하고, 그림은 빼고 HTML만 만든 뒤 다음으로 갑니다.

**끝나면 남는 것:** `outputs/오늘이슈.md`, `outputs/이슈그림.png`, `outputs/이슈설명.html`

## 휴식 시간에 할 일 — 3교시 업무 공간 설치

1교시가 끝난 휴식 시간(14:20)에 3교시에 쓸 내 업무 공간을 설치합니다. 휴식 시간에 못 했으면 3교시를 시작할 때 합니다. 2교시 실습은 [2교시 안내](#mixed-2-01-data)에서 받습니다.

**Windows** — 시작 버튼을 누르고 `PowerShell`을 입력해 **Windows PowerShell**을 엽니다. 파란(또는 검은) 창에 아래 한 줄을 붙여 넣고 Enter를 누릅니다.

```powershell
irm https://raw.githubusercontent.com/axwith/tes-workmate/main/get.ps1 | iex
```

**Mac** — Spotlight(⌘+스페이스)에서 `터미널`을 찾아 열고, 아래 한 줄을 붙여 넣고 Enter를 누릅니다.

```bash
curl -fsSL https://raw.githubusercontent.com/axwith/tes-workmate/main/install.sh | bash
```

1. 설치 중 `기본 검색에 더할 업무 폴더 경로`를 묻습니다. 아무것도 넣지 말고 Enter를 누릅니다.
2. 마지막에 `발견 파일 수`, `본문 추출 수`, `설치 완료`가 나오면 됩니다.

![PowerShell 설치 완료와 발견 파일 수와 본문 추출 수가 보이는 장면](/images/rnd/r3-01-install.jpg)

기억 자동 정리 등록이 실패해도 설치는 끝난 것입니다.

3. 이어서 설치된 폴더가 파일 탐색기(Mac은 Finder)로 열립니다. 확인만 하고 닫아도 됩니다. Codex에서 여는 것은 3교시에 합니다.

설치 위치는 Windows `문서\tes-workmate`(OneDrive를 쓰는 PC는 `OneDrive\문서\tes-workmate`), Mac `~/Documents/tes-workmate`입니다. 설치 중 오류가 보이면 혼자 다시 실행하지 말고 손을 듭니다.
